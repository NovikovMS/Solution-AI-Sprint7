# ADR-краткая запись — Распознавание и оцифровка сканов документов кредитной заявки (№ 2)

Короткая запись: решение по данным, размещению и модели с допущениями и триггерами пересмотра. Полные разделы 2–5 паспорта — в `passport_2.md`.

## Контекст

Андеррайтинг разбирает пакет документов кредитной заявки ~1,5 ч/заявка.

- **Форматы документов разнородные:** Excel, PDF-сканы, выгрузки из бухгалтерских систем, фото с телефона.
- **Структура документов стандартная:** бухгалтерская отчётность, выписки, справки.
- **Эталон для проверки извлечения:** есть для структурированных выгрузок и выписок, для сканов его нет.
- **Чувствительность:** в документах — банковская тайна и ПДн.

## Жёсткие ограничения

- **Право:** сканы/фото содержат ПДн и банковскую тайну — передача за контур и размещение определяют комплаенс/DPO/юристы. До ответа варианты с передачей сканов за контур не допускаются.
- **Воспроизводимость:** для кредитного решения нужна воспроизводимость извлечения — закрепление версии или регрессионный прогон.
- **Галлюцинации:** модель должна возвращать пустое значение, когда поля в документе нет, а не додумывать правдоподобное. Придуманное значение критичного поля уйдёт в кредитное решение, и перепроверить его уже будет некому.

## Рассмотренные варианты размещения

| Вариант | Пилот | Прод |
|----------|:----:|:----:|
| Публичный API (сквозной PDF → мультимодальная модель) | допустимо (обезличенные/синтетика) | отклонён (ПДн/банковская тайна в сканах) |
| Выделенный контур провайдера | кандидат | кандидат |
| Self-hosting в облаке (локальный OCR) | кандидат | кандидат |
| On-prem (локальный OCR) | допустимо | кандидат |
| Гибрид (локальный OCR + выделенный контур) | — | кандидат |

## Решение

- **Пилот — свой контур в облаке: документ один раз распознаём локально, дальше с текстом работает компактная текстовая модель.** Локальное распознавание даёт каноническое представление документа, которое переиспользуют и другие сценарии, а наружу уходит только нормализованный текст без лишних данных. Для Excel и структурированных выгрузок распознавание не нужно вовсе — там работает обычный парсер.
- **Прод — не выбран окончательно.** Кандидаты два: держать всё on-prem либо оставить распознавание у себя, а текстовую модель вынести в выделенный контур. Сквозной вызов, когда PDF целиком уходит в мультимодальную модель через публичный API, отклонён по жёстким ограничениям — в сканах ПДн и банковская тайна. Выбираем после сквозного сравнения обоих путей по качеству, задержке и стоимости владения.

## Решение по модели (предварительное)

- **Пилот:** локальное распознавание плюс компактная текстовая модель, которая извлекает поля, указывает место в документе, откуда взято значение, и оценивает свою уверенность по каждому полю. Для структурированных выгрузок — обычный парсер.
- **Прод (предварительно):** тот же кандидат, подтверждённый приёмочным прогоном. Альтернатива — мультимодальная модель, если сквозной путь окажется лучше по качеству и уложится в задержку и стоимость. Условие принятия — подтверждение порогов F1 по полям на размеченной выборке сканов.

## Допущения

- Эталона для сканов нет, его придётся размечать вручную. План: написать гайдлайн по полям и разметить силами андеррайтеров порядка нескольких тысяч сканов.
- Профиль нагрузки в проде неизвестен. Ориентир — поток кредитных заявок, это тысячи в год, а не миллионы.
- Для пилота хватит структурированных выгрузок, по которым эталон уже есть. Сканы подключаем по мере разметки.

## Риски

- Модель придумает значение критичного поля, и оно уйдёт в кредитное решение. Смягчаем валидацией формата и обязательным подтверждением критичных полей человеком.
- Скан окажется плохого качества, распознавание деградирует. Смягчаем фолбэком на ручной ввод или отдельной обработкой таких документов.
- Зависимость от вендора при работе в выделенном контуре. Смягчаем адаптером и планом выхода.
- Изменится регулирование в части размещения сканов с ПДн.

## План выхода от вендора

Адаптер перед моделью (единый выходной контракт — поля с привязкой к источнику + уверенность). Миграция на второго поставщика/другую модель — N недель. Локальный OCR закрепляется отдельно от модели — обновление модели не меняет чтение документа.

## Триггеры пересмотра

- F1 по критичным полям не дотянул до порога на размеченной выборке → переводим критичные поля на ручной ввод, модель оставляем только для остальных.
- Доля документов с полной ручной правкой выросла по сравнению с текущей → пересматриваем конвейер.
- Экономия времени на заявку оказалась вдвое меньше расчётной → пересматриваем размещение и модель либо закрываем проект.
- Изменились закон, цены или условия SLA вендора.
- Пошли документы в новых форматах — например, фото с телефона или незнакомые шаблоны бухгалтерии → собираем и размечаем их отдельно.
