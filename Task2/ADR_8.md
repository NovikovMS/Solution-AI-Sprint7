# ADR-краткая запись — Предсказание оттока клиентов (№ 8)

Короткая запись: решение по данным, размещению и модели с допущениями и триггерами пересмотра. Полные разделы 2–5 паспорта — в `passport_8.md`.

## Контекст

~180 тыс. активных клиентов-юрлиц/ИП, история операций за несколько лет.

- **Из контекста:** ~600 ложных приостановок/мес, 120 жалоб, часть уходит в другой банк.
- **Постановка:** выстроить клиентов группы риска по очерёдности обзвона. Модель только подсказывает порядок, а звонит и предлагает условия персональный менеджер.
- **Метка оттока:** наблюдаема по факту закрытия счёта/падения активности.
- **Чувствительность:** ПДн клиентов-юрлиц, представителей, поручителей-физлиц; агрегаты по оборотам могут составлять банковскую тайну.

## Жёсткие ограничения

- **Право:** ПДн клиентов и поручителей-физлиц — основания обработки, обезличивание, регион хранения определяют комплаенс/DPO/юристы. Для ранжирования на агрегатах чувствительность ниже, но агрегаты по оборотам — банковская тайна. До ответа варианты с передачей агрегатов за контур не допускаются.
- **Не блокировка:** модель не принимает решение о действии над клиентом — только рекомендует. Полностью автоматическое действие недопустимо (риск раздражения лояльных клиентов).
- **Воспроизводимость:** для разбора жалоб нужна воспроизводимость ранга — закрепление версии или регрессионный прогон.

## Рассмотренные варианты размещения

| Вариант | Пилот | Прод |
|----------|:----:|:----:|
| Публичный API | допустимо (обезличенные агрегаты) | отклонён (банковская тайна в агрегатах по оборотам) |
| Выделенный контур провайдера | допустимо | кандидат |
| Self-hosting в облаке (свой контур) | кандидат | кандидат |
| On-prem | допустимо | кандидат |
| Гибрид | — | допустимо |

## Решение

- **Пилот — свой контур в облаке.** Данные не покидают периметр: ПДн и банковская тайна наружу не уходят. Модель работает на агрегатах поведения клиента, ей достаточно CPU, GPU не нужен.
- **Прод — не выбран окончательно.** Кандидаты: перенести всё on-prem ради полной изоляции либо остаться в своём контуре в облаке. Публичный API отклонён по жёстким ограничениям — агрегаты по оборотам составляют банковскую тайну. Выбираем после замера нагрузки и подтверждения модели.

## Решение по модели (предварительное)

- **Ансамбль деревьев на агрегатах поведения клиента** — градиентный бустинг, случайный лес или подобный. Зрелая технология, работает на CPU, а главное — показывает топ-факторы, по которым менеджер понимает вероятную причину ухода и подбирает меру удержания. Конкретный алгоритм внутри семейства выбирает DS-команда на приёмочном прогоне: на архитектуру, размещение и стоимость он не влияет. Условие принятия — подтверждение порогов precision@k и recall@k при разделении выборки по времени: обучаем на раннем периоде, проверяем на более позднем.
- Как точку отсчёта берём логистическую регрессию — она полностью интерпретируема. LLM не рассматриваем: текста на входе нет, задача целиком на табличных признаках.

## Допущения

- Порог факта оттока и горизонт прогноза не заданы — их уточняем у бизнеса. Разрыв здесь в постановке, а не в данных.
- Профиль нагрузки в проде неизвестен.
- Стоимость одного контакта и ценность сохранённого клиента тоже за бизнесом — без них не посчитать окупаемость удержания.

## Риски

- Модель ошибочно поднимает лояльных клиентов, их начинают обзванивать, и лишний контакт сам подталкивает к уходу. Смягчаем guardrail на долю лояльных в top-k и контрольной группой.
- Модель деградирует на новых сегментах — например, на селлерах маркетплейсов, которых не было в обучении.
- Зависимость от вендора при работе через API или выделенный контур. Смягчаем адаптером и планом выхода.
- Изменится регулирование в части трансграничной передачи данных.

## План выхода от вендора

Адаптер перед моделью (единый выходной контракт — вероятность + топ-факторы). Миграция на другого поставщика/другую модель — N недель. При self-hosting — ниже зависимость, выше операционная нагрузка.

## Триггеры пересмотра

- precision@k ≤ baseline → закрываем ML, остаёмся на реактивном удержании.
- ROI контакта отрицательный → пересматриваем бюджет/меры, возможно закрываем.
- Доля лояльных в top-k выше порога → откат, guardrail нарушен.
- Деградация на новом сегменте → фолбэк, не контактируем этот сегмент по модели.
- Изменение закона/цен/SLA вендора.
