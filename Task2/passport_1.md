# Паспорт инициативы № 1 — Выявление подозрительных операций (флагман)

Разделы 2–5 паспорта: постановка, качество, данные, эксперимент. Раздел 0 (канвас) и раздел 1 (триаж) — в `Task1/`.

---

## Раздел 2. Постановка

- **Бизнес-цель:** изменить порядок очереди операций, разбираемых финмониторингом, так, чтобы доля действительно подозрительных в разобранной выборке росла при той же пропускной способности.
- **Объект решения:** одна операция по счёту клиента (платёж) с атрибутами — сумма, назначение платежа (свободный текст), контрагент, ОКВЭД, дата, канал; плюс агрегаты по клиенту и контрагенту за окно (обороты, частота, доля транзитных паттернов, разбивка платежей под пороги).
- **Входные данные:** табличные признаки + свободный текст назначения платежа. Документов и изображений на входе нет.
- **Операция:** ранжирование — расставить операции по степени подозрительности.
- **Результат модели:** скор/ранг подозрительности + топ-факторы (для объяснимости). Это **не** вердикт «схема/не схема».
- **Результат для бизнеса:** переупорядоченная очередь для ручной проверки. Детерминированные пороговые правила работают параллельно и помечают операции независимо. Вердикт, отказ в проведении, снятие пометки — за сотрудником по результатам разбора.
- **Дальнейшее действие:** сотрудник разбирает top-N операций; решение об эскалации на расследование принимает сам.
- **Источник правильного ответа:** готовой разметки нет. Три следа разной надёжности — «эскалировано» (~400/мес), исход расследования, формально подтверждённые (единицы, спустя месяцы). Ни один не эталон. Непроверенная операция ≠ чистая (очередь формировалась правилами — смещение отбора).
- **Роль правил и человека:** правила помечают и фильтруют, модель ранжирует, человек разбирает и решает. Модель не блокирует платёж.
- **Открытые вопросы:** допустимо ли, чтобы модель только меняла порядок очереди (вопрос бизнесу/комплаенсу); порог факта «схема» и горизонт — у юристов/финмониторинга.

### Развилка получения сигнала

Для обучения с учителем эталона нет. Развилка (см. также ADR):

- **Путь A — слабые метки + постановка без учителя:** ранжирование на слабых следах с оговоркой, что модель воспроизводит логику правил. Дёшево и быстро, ограничено в качестве. Это режим пилота.
- **Путь B — разметка силами финмониторинга по гайдлайну:** целевая разметка выборки с оценкой согласованности (κ Кохена/Флейсса). Дороже и дольше, даёт эталон. Это целевой прод.
- **Путь C — вероятностная контрольная выборка:** случайная/стратифицированная по сегментам и суммам выборка из **всего** потока (не из очереди), размеченная экспертами. Несмещённая оценка непроверяемой части, приёмочный набор.

**Рекомендация:** гибрид A+C для пилота (ранжирование на слабых метках, качество мерим на C), переход к B для целевого прода. Разметка копится из двух источников — разобранная приоритетная очередь + контрольная выборка. Брать только очередь нельзя — новое смещение собственного производства.

## Раздел 3. Качество

- **Бизнес-действие:** операция попадает в очередь ручной проверки раньше или позже (приоритизация), а не блокировка.
- **Положительный класс:** операция — действительно подозрительная (по гайдлайну/исходу расследования). На пилоте — слабая метка «эскалировано/подтверждено», с оговоркой.
- **Метрика, связанная с решением:** это ранжирование, не классификация. Главные — precision@N (доля действительно подозрительных среди top-N, которые финмониторинг успевает разобрать), recall@N, и сумма предотвращённых потерь среди top-N. **Не** accuracy и не «92% точности».
- **Baseline:** текущий процесс — порядок очереди определяют пороговые правила и внешние сигналы (по сумме/времени). Сравнение: сколько действительно подозрительных находит текущая очередь в top-N vs то же N после модели.
- **Выборка для проверки:** вероятностная контрольная выборка из всего потока (путь C), размеченная экспертами — несмещённая. Разобранная очередь даёт метки, но они смещённые (отбор правилами) — для обучения с оговоркой, для независимой оценки — только C.
- **Рабочая точка:** выбирается по пропускной способности финмониторинга (~10 тыс. разбирают в месяц). Рабочая точка — top-N на разбор, где N = пропускная способность. Не порог вердикта.
- **Показатели в рабочей точке:** precision@N, recall@N, нагрузка на очередь (=N, фиксирована), сумма предотвращённых схем в top-N, доля новых сегментов в top-N.
- **Стоимость ошибок:** FP = лишняя проверка (~12 мин × ставка сотрудника); FN — при ранжировании это не пропуск, а уход схемы из top-N в непроверяемую часть потока (риск предписания/ущерб). Цена асимметрична: пропуск дороже лишней проверки.
- **Guardrails:** доля подтверждённых подозрений в разобранной выборке не должна упасть vs baseline; доля ложных приостановок и жалоб не должна вырасти; время до разбора критичных случаев не должно ухудшиться; покрытие новых сегментов мониторится.
- **Допущения и открытые вопросы:** пропускная способность фиксирована; метка слабая; новые схемы не покрыты обучением; порог «действительно подозрительная» уточняется у финмониторинга.

## Раздел 4. Данные

| Поле | Значение |
|------|---------|
| Решение | Приоритизация очереди ручной проверки операций |
| Объект и гранулярность | Операция по счёту (платёж) + агрегаты по клиенту/контрагенту за окно |
| Источник и владелец | АБС/операционный дневник (признаки), финмониторинг (метки эскалации/расследования), комплаенс/DPO/юристы (право) |
| Сигнал / источник правильного ответа | Три слабых следа, ни один не эталон. Путь A+C для пилота, B для целевого прода |
| Доступность признаков после запуска | Агрегаты по клиенту/контрагенту и назначение доступны в момент операции. Поля «результат расследования/отметка эксперта» для новой операции не существуют — использование даёт утечку из будущего |
| Разметка | Готовой нет. План: гайдлайн + разметка контрольной выборки (путь C) + разметка разобранной очереди. Согласованность — κ Кохена/Флейсса, минимальный порог согласия фиксируется до разметки |
| Смещение отбора | Ключевое. Очередь формировалась пороговыми правилами и внешними сигналами → обучение на ней воспроизводит логику правил. Непроверенная ≠ чистая. Поэтому — вероятностная контрольная выборка из всего потока |
| Репрезентативность | История за годы есть по текущим сегментам. Новые сегменты (напр. селлеры маркетплейсов) не покрыты — на момент пилота репрезентативна по текущим, на проде — риск |
| Объём | 20–25 млн операций/мес, за годы — десятки/сотни млн. Но важный класс редок: ~400 эскалаций/мес, подтверждённых — единицы. Объём важного класса мал |
| Качество | Назначение — свободный текст, пропуски, дубли, разные форматы выгрузок. Формат ≠ низкое качество (скан/PDF — другой вид входа) |
| Право на использование | Банковская тайна + ПДн (ИП, поручители-физлица). AML — обязанность банка. Вопросы комплаенсу/DPO/юристам: основания обработки, обезличивание, регион хранения, допустимость ранжирования. Вердикт — не архитектора |
| Разрыв и план устранения | Нет эталонной разметки.<br><br>План: путь A (слабые метки + ранжирование) — для пилота.<br><br>Путь C (контрольная выборка) — для измерения качества.<br><br>Путь B (разметка по гайдлайну, ~полгода) — для целевого прода |

**Вердикт по готовности данных:**

- **Для пилота — Pilot-ready:** ранжирование на слабых метках доступно сразу (путь A), параллельно копится контрольная выборка (путь C). Архитектура ML-сервиса не преждевременна, потому что сервис не выносит вердикт, а меняет порядок очереди.
- **Для целевого прода — Gap с планом:** нужен эталон (путь B), которого нет; план закрытия — гайдлайн + разметка выборки силами финмониторинга с оценкой согласованности, горизонт ~полгода. Переход к прод-версии — после подтверждения порогов на размеченной выборке.

Не **Blocked**: реалистичный путь получения сигнала есть. Не **Ready**: эталона нет.

## Раздел 5. Эксперимент (план пилота)

### Какие неопределённости проверяет пилот

1. Даёт ли ранжирование на слабых метках (путь A) прирост действительно подозрительных в top-N vs текущая очередь (baseline) при той же пропускной способности.
2. Не растёт ли доля ложных приостановок и жалоб (guardrails).
3. Как ведёт себя модель на операциях без истории (новый клиент/контрагент) и на свободном тексте назначения.
4. Какова фактическая стоимость разбора и сравнение с эффектом.

### Приёмочный набор

Вероятностная контрольная выборка из **всего** потока (не из очереди), стратифицированная по сегментам и суммам, размеченная экспертами по гайдлайну. Объём для оценки precision@N при редком классе — порядка нескольких тысяч размеченных операций в контрольной выборке; точное число определяется на пилоте (объём — через пилот, не по универсальному числу). Для обучения — история операций за несколько лет со слабыми метками.

### Метрики и пороги

- precision@N (доля действительно подозрительных в top-N) — порог = baseline + X%, где X — из экономики: стоимость разбора одной операции vs стоимость пропуска схемы. Источник порога — экономика разбора и ущерба, не «92%».
- recall@N — ориентир.
- Сумма предотвращённых потерь среди top-N — главный бизнес-показатель.
- Guardrails: доля ложных приостановок/жалоб не выше baseline; доля подтверждённых в разобранной выборке не ниже baseline.

### Что означает провал на сценарии

- precision@N ≤ baseline при той же нагрузке → ранжирование не даёт прироста, ML в этом звене не нужен, остаёмся на правилах.
- Рост ложных приостановок/жалоб → откат, guardrail нарушен.
- Деградация на операциях без истории (новый клиент) → фолбэк на детерминированные правила для этого сегмента, модель не пускаем в разбор таких операций.

### При каком результате решение меняется

- precision@N ≤ baseline → проект честно закрываем, ML не нужен.
- precision@N > baseline на согласованную величину → идём в целевой прод: запускаем программу разметки по гайдлайну (путь B), параллельно копим контрольную выборку, переводим сервис на эталонные метки.
- Появление нового сегмента (напр. селлеры) с иной картиной → триггер пересмотра (см. ADR).
